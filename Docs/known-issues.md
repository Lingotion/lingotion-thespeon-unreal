# Known Issues and Limitations
**These issues are known and are currently being addressed by the Lingotion development team. If you find any other issues, please create a new issue through the [GitHub repository](https://github.com/Lingotion/lingotion-thespeon-unreal/issues/new).**
* The first synthesis has higher latency and performance impact than subsequent syntheses due to buffer initializations. We recommend using `PreloadCharacter` to load the models into memory before synthesis where possible.
* The Audio Sample Request control character is currently supported at most once per word. If a word contains several, all except the last are ignored.
* Number-to-words conversion only supports simple numeric formats: integers (e.g., "42"), decimals with a single decimal point (e.g., "3.14"), and ordinals (e.g., "1st", "2nd"). Locale-specific formats such as thousand separators ("1,000,000" or "1 000 000") and comma decimals ("3,14") are not supported. Negative numbers use "minus" (e.g., "-5" becomes "minus five"). The built-in conversion is intended for simple string concatenation with numerical variables or ordinals, e.g., "I have {nbr} coins in my pocket." or "This is the {MakeOrdinal(MyInteger)} time that happened."
* Any Audio Sample Request characters placed inside a numerical or ordinal value will be ignored. As a workaround, write the number out in words and insert the Audio Sample Request character as you see fit.
